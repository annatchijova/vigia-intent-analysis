Для обеспечения идемпотентности каждая фаза проверяет отсутствие сторожевых маркеров $\mu$ перед модификацией; при обнаружении $\mu$ фаза пропускается, что даёт тождественное преобразование $\mathcal{P}(f, \delta) = f$.

Входные спецификации требуют запуска модуля из корня проекта VIGÍA, обеспечивая корректное разрешение относительных путей ко всем целевым файлам. Обязательные входные данные включают: (i) переменную окружения `VIGIA_PROJECT_ROOT` или эквивалентный токен валидации пути; (ii) отчёт автоматизированного аудита безопасности в формате JSON, перечисляющий находки P0 $F = \{f_1, f_2, f_3\}$; (iii) манифест патча — детерминированный артефакт YAML или JSON, специфицирующий $\delta_1, \delta_2, \delta_3$ с криптографическими контрольными суммами по каждому параметру; а также (iv) права на запись в поддерево исходного кода `vigia/`. Опциональные входные данные охватывают константы распада $\lambda$ и пороговые значения ресурсных границ $\vec{r}_{\max}$, которые при отсутствии принимают значения, генерируемые CAIE. Выходные артефакты состоят из трёх модифицированных исходных модулей, дописываемого файла `patch_log.jsonl`, содержащего записи с метками времени (UTC) о хешах до и после патча $\{H_{\text{pre}}, H_{\text{post}}, \delta_i, \text{timestamp}, \text{executor\_uid}\}$, а также файла `determinism_proof.txt`, кодирующего корень Меркла $R = \mathcal{M}(f'_1, f'_2, f'_3)$ набора пропатченных файлов. Модуль завершается с кодом 0 при побитово верифицированном успехе, кодом 1 при нарушении валидации входных данных, кодом 2 при конфликте патча (например, несоответствие сторожевого маркера или конкурентная модификация) и кодом 3 при обнаружении недетерминизма через расхождение хешей.

Детерминированные гарантии модуля формально характеризуются побитовой воспроизводимостью, идемпотентностью и противоправочной регистрацией событий. Побитовая воспроизводимость утверждает, что при идентичных входных данных $(I, E)$, где $I$ — кортеж входных артефактов, а $E$ — среда выполнения, ограниченная Python 3.10+ и детерминированным порядком обхода файловой системы, выходная битовая строка $O$ инвариантна относительно повторных запусков: $\forall E_1, E_2: O(E_1) \equiv O(E_2)$. Данное свойство верифицируется посредством сравнения деревьев Меркла всех выходных артефактов. Идемпотентность гарантирует, что повторное применение идентичных спецификаций патча не вызывает дальнейших мутаций состояния сверх первого применения, формально $\mathcal{P}^n(f, \delta) = \mathcal{P}(f, \delta)$ при $n \geq 1$. Журнал аудита поддерживает судебные стандарты цепочки сохранности за счёт реализации последовательного криптографического связывания: каждая запись $L_n$ заверяет предшествующую через $L_n = H(L_{n-1} \,\|\, \text{entry}_n)$, что делает ретроспективную фальсификацию вычислительно неосуществимой в силу свойств устойчивости к прообразу хеш-функции SHA-256. Совокупность этих свойств удовлетворяет стандарту Дауберта (Daubert) для допустимости научных доказательств, поскольку модуль демонстрирует известную частоту ошибок, стремящуюся к нулю при наложении патча, прошёл рецензирование в консорциуме VIGÍA и придерживается стандартизированных судебных методологий. Дополнительно модуль соответствует требованиям стандарта GB/T 22239-2019 (основные требования по классифицированной защите сетевой безопасности) и уровню 3 схемы MLPS 2.0 в части управления патчами безопасности, целостности базовой конфигурации и ведения комплексных аудиторских следов. Если судебная база данных содержит персональную информацию (PII), установка заглушки соблюдает требования GB/T 35273-2020 относительно шифрования при передаче, гарантируя, что восстановленная связность не приведёт к экспозиции открытых текстовых доказательных данных.

Интеграция со смежными модулями VIGÍA носит структурный и операционный характер. Сущность `trust_decay` непосредственно потребляется модулем `vigia.security.caie`, осуществляющим оценку контекстных показателей целостности для доказательных артефактов. Минимальная база данных заглушки восстанавливает плоскость данных для `vigia.nlp.adversarial_pipeline`, обеспечивая возможность проведения тестов состязательной робастности на судебных текстовых корпусах. Упрочнённый `vigia.core.execution_controller` транслирует гарантии границ в нисходящие аналитические движки, включая `vigia.analysis.heuristic_engine` и `vigia.ml.inference_orchestrator`. Криптографическое хеширование делегируется модулю `vigia.crypto.hasher`, предоставляющему реализации SHA-256, используемые при построении корня Меркла. Наконец, вся телеметрия и журналы патчей поглощаются модулем `vigia.audit.logger` для долгосрочного архивирования и формирования отчётов о соответствии нормативным требованиям. Таким образом, `scripts/fix_security_init.py` функционирует не просто как сценарий устранения неполадок, но как формально обоснованный, аудиторски детерминированный инструмент для упрочнения судебной инфраструктуры в рамках экосистемы VIGÍA.

## 中文

`scripts/fix_security_init.py`模块是VIGÍA取证框架中一个确定性的零优先级（P0）部署补丁。该脚本设计为仅在项目根目录下执行，用于修复由自动化静态与动态分析流程识别的关键安全偏差。其操作使命涵盖三个独立的加固域：（1）通过向安全初始化层注入参数化`trust_decay`模型，激活上下文感知完整性评估器（CAIE）；（2）通过安装最小化接口存根（stub），恢复取证数据库与对抗式自然语言处理（NLP）管道之间的连通性；（3）在核心执行控制器中实施严格的运行时边界约束。模块实施的每一次变换均按位可复现，从而保障取证可采性所需的加密保管链，并支持跨机构验证。

该模块的数学基础建立在形式化补丁代数与连续信任衰减模型之上。设$\mathcal{F}$为VIGÍA代码库中全部源文件的集合，$\Delta$为语义有效的补丁规范集合。模块实现了一个确定性补丁算子$\mathcal{P}: \mathcal{F} \times \Delta \to \mathcal{F}'$，使得对于任意文件$f \in \mathcal{F}$与补丁$\delta \in \Delta$，结果文件$f' = \mathcal{P}(f, \delta)$满足功能等价与语法有效性条件。确定性形式化表现为抗碰撞哈希函数$H$对输出的不变性：$H(\mathcal{P}(f, \delta)) = c$，其中常数$c$在所有有效执行环境$E$中保持不变。此外，该算子具有幂等性，满足$\mathcal{P}(f', \delta) = f'$，从而在重复应用时防止有害的累积突变。`trust_decay`注入实现了一个时变信任度量$T: \mathbb{R}_{\geq 0} \to [\epsilon, 1]$，其定义为$T(t) = T_0 e^{-\lambda t} + \epsilon$，其中$T_0 \in (0,1]$为初始信任分值，$\lambda > 0$为由CAIE风险引擎校准的衰减常数，$\epsilon \in (0, T_0)$为非零下限，用于缓解完全信任崩溃。该指数衰减模型确保证密断言与完整性令牌以可预测方式衰减，迫使CAIE模块（`vigia.security.caie`）在运行时重新评估上下文信任边界。对于第三个加固向量，运行时边界约束被建模为在资源向量$\vec{r} = (c, m, t, n) \in \mathbb{R}^4$上的受限优化问题，该向量分别代表CPU周期、内存占用、时间跨度与网络出流量。经修补的执行控制器保证，对于任意取证任务$\tau$，均满足$\vec{r}(\tau) \in \mathcal{B}$，其中$\mathcal{B} = \{\vec{r} \in \mathbb{R}^4 \mid c \leq C_{\max}, m \leq M_{\max}, t \leq \Delta t_{\max}, n \leq N_{\max}\}$为由组织策略定义的可接受资源多面体。

`scripts/fix_security_init.py`执行的算法协议包含三个顺序阶段，每一阶段均受前置条件检查与后置条件哈希验证的约束。在第一阶段，脚本解析安全初始化模块的抽象语法树（AST）——通常位于`vigia/security/__init__.py`——以定位`SecurityConfig`单例。随后，脚本注入一个`TrustDecayModel`类的实例化语句，其参数取自`security_audit.json`清单。该注入通过在完整性评估循环内注册衰减回调函数来激活CAIE。第二阶段处理位于`vigia/db/forensic_interface.py`的取证数据库接口。算法合成最小化存根$S_{\min}$，其严格遵循接口契约$\mathcal{I} = \{\text{connect}, \text{query}, \text{validate}, \text{close}\}$。该存根通过实现类型兼容的适配器方法并保留现有模式迁移元数据，恢复持久化取证数据存储与对抗式NLP管道（`vigia.nlp.adversarial_pipeline`）之间的双向连通性。第三阶段针对核心执行控制器（`vigia/core/execution_controller.py`）。算法对主执行循环进行插桩，注入前置钩子$h_{\text{pre}}$与后置钩子$h_{\text{post}}$。前置钩子计算投影资源向量$\vec{r}_{\text{proj}}$，若$\vec{r}_{\text{proj}} \notin \mathcal{B}$，则抛出`VIGIA_RuntimeBoundaryException`异常。后置钩子将观测到的资源消耗记录至审计子系统。为确保幂等性，每一阶段在修改前均验证哨兵标记$\mu$的不存在；若检测到$\mu$，则跳过该阶段，产生恒等变换$\mathcal{P}(f, \delta) = f$。

输入规范要求从VIGÍA项目根目录调用本模块，以确保所有目标文件的相对路径解析正确。必填输入包括：（i）环境变量`VIGIA_PROJECT_ROOT`或等效路径验证令牌；（ii）自动化安全审计报告，以JSON文档形式枚举P0级发现项$F = \{f_1, f_2, f_3\}$；（iii）补丁清单，即一个确定性的YAML或JSON制品，以加密校验和逐参数指定$\delta_1, \delta_2, \delta_3$；（iv）对`vigia/`源码子树的写权限。可选输入包括衰减常数$\lambda$与资源边界阈值$\vec{r}_{\max}$；若缺失，则默认采用CAIE生成的数值。输出制品包括三个已修改的源模块、一个仅追加的`patch_log.jsonl`文件（包含带UTC时间戳的补丁前后哈希记录$\{H_{\text{pre}}, H_{\text{post}}, \delta_i, \text{timestamp}, \text{executor\_uid}\}$），以及一个`determinism_proof.txt`文件（编码已修补文件集合的Merkle根$R = \mathcal{M}(f'_1, f'_2, f'_3)$）。模块在按位验证成功时返回代码0，输入验证失败时返回1，补丁冲突（如哨兵不匹配或并发修改）时返回2，通过哈希差异检测到非确定性时返回3。

该模块的确定性保证在形式上以按位可复现性、幂等性与防篡改日志记录为特征。按位可复现性断言：在相同输入$(I, E)$下，其中$I$表示输入制品元组，$E$表示受限于Python 3.10+与确定性文件系统遍历顺序的执行环境，输出比特串$O$在不同执行间保持不变：$\forall E_1, E_2: O(E_1) \equiv O(E_2)$。该性质通过对所有输出制品的Merkle树比较进行验证。幂等性确保对相同补丁规范的重复应用不会导致首次应用之外的额外状态突变，形式上满足$\mathcal{P}^n(f, \delta) = \mathcal{P}(f, \delta)$（$n \geq 1$）。审计日志通过顺序加密链接维护取证保管链标准：每条日志记录$L_n$通过$L_n = H(L_{n-1} \,\|\, \text{entry}_n)$向前序记录做出密码学承诺，从而在SHA-256的原像抗性下使追溯性篡改在计算上不可行。这些性质共同满足科学证据可采性的Daubert标准，因为模块在补丁应用上表现出的已知错误率趋近于零，已接受VIGÍA联盟的同行评审，并遵循标准化取证方法论。此外，模块符合GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》及MLPS 2.0第三级要求，涉及安全补丁管理、基线配置完整性与全面审计线索生成。若取证数据库保留个人可识别信息（PII），则存根安装遵循GB/T 35273-2020关于传输加密的规定，确保恢复的连通性不会暴露明文证据数据。

与相邻VIGÍA模块的集成兼具结构性与操作性。`trust_decay`实体由`vigia.security.caie`直接消费，该模块对证据制品执行上下文完整性评分。最小化数据库存根为`vigia.nlp.adversarial_pipeline`恢复数据平面，使其能够对取证文本语料库进行对抗鲁棒性测试。加固后的`vigia.core.execution_controller`将边界保证向下游分析引擎传播，包括`vigia.analysis.heuristic_engine`与`vigia.ml.inference_orchestrator`。加密哈希计算委托给`vigia.crypto.hasher`，该模块提供用于Merkle根构造的SHA-256实现。最终，所有遥测数据与补丁日志均由`vigia.audit.logger`摄取，用于长期归档与合规报告。综上所述，`scripts/fix_security_init.py`不仅是修复脚本，更是VIGÍA生态系统中一个形式化基础扎实、具备可审计确定性的取证基础设施加固工具。
