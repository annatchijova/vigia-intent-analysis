## ENGLISH

`vigia/phonetic_loader.py` constitutes a core deterministic ingestion subsystem within the VIGÍA forensic phonetic analysis framework. Its primary forensic purpose is to eliminate non-deterministic variability during the loading phase of phonetic dictionary resources. In forensic speech science, the integrity of phoneme-to-grapheme mappings directly conditions the reliability of downstream transcription, speaker identification, and phonetic comparison pipelines. By consolidating fragmented source pathways into a single canonical ingestion route, the module ensures that every forensic examination initiates from an identical, validated, and auditable lexical substrate. This design satisfies the reproducibility prerequisites mandated by the Daubert standard for scientific evidence under Federal Rules of Evidence 702, as well as the data-integrity requirements specified in Chinese national standard GB/T 29360-2012 concerning electronic data forensic inspection.

The operation of `vigia/phonetic_loader.py` is formally grounded in relational algebra and deterministic function theory. Let $\mathcal{S}$ denote the set of all possible source filesystem paths, including relative paths, symbolic links, and environment-relative descriptors. The canonical path resolution operator is defined as a surjective function:

$$C: \mathcal{S} \to \mathcal{T}, \quad \forall s \in \mathcal{S}, \; C(s) = \tau$$

where $\mathcal{T}$ represents the set of absolute, normalized, inode-verified canonical paths. The injectivity condition holds for path-equivalence classes: if $s_1 \sim s_2$ (denoting resolution to the same file content and metadata), then $C(s_1) = C(s_2)$. Let $\mathcal{P} = \{p_1, p_2, \dots, p_m\}$ be the phoneme alphabet and $\mathcal{G} = \{g_1, g_2, \dots, g_n\}$ the grapheme alphabet. A raw phonetic dictionary $d \in \mathcal{D}$ is modeled as a finite set of ordered pairs:

$$d = \{(p_i, g_j) \mid p_i \in \mathcal{P}, g_j \in \mathcal{G}\} \subseteq \mathcal{P} \times \mathcal{G}$$

Schema validation is formalized as a Boolean predicate:

$$V: \mathcal{D} \times \Sigma \to \{0, 1\}, \quad V(d, \sigma) = \begin{cases} 1 & \text{if } d \text{ conforms to schema } \sigma \in \Sigma, \\ 0 & \text{otherwise}. \end{cases}$$

The deterministic ingestion transformation $I$ is then defined as:

$$I: \mathcal{D} \times \Theta \times \Sigma \to \mathcal{M}, \quad I(d, \theta, \sigma) = M^*$$

where $\Theta$ is the configuration parameter space (including normalization forms, source-priority vectors, and collision-resolution policies) and $\mathcal{M}$ is the codomain of validated, immutable phonetic mappings. The fundamental deterministic axiom requires:

$$\forall t_1, t_2 \in T, \quad I(d, \theta, \sigma; t_1) = I(d, \theta, \sigma; t_2)$$

meaning the mapping is temporally invariant given identical inputs and parameters. This invariance is essential for forensic reproducibility and satisfies the error-rate prong of the Daubert admissibility framework.

The module executes a multi-stage ingestion pipeline comprising five principal phases. In the first phase, *Canonical Path Resolution and Alias Elimination*, the algorithm applies the function $C$ to every declared source path $s$. Symbolic links are dereferenced, relative segments are absolutized against a forensic working directory $\omega$, and filesystem aliases are resolved via inode-content fingerprinting. The output is a deduplicated sequence of canonical paths $\tau_1, \tau_2, \dots, \tau_k$. In the second phase, *Pre-Ingestion Cryptographic Fingerprinting*, each resolved file is hashed using a cryptographically secure function $H$ (e.g., SHA-256) to produce a content digest $h_k = H(\text{read}(\tau_k))$. This digest is immediately registered with `vigia/chain_of_custody_logger.py`, establishing an auditable provenance record. In the third phase, *Schema Retrieval and Structural Validation*, the module queries `vigia/schema_registry.py` for the active schema $\sigma$ identified by `schema_id`. Each dictionary entry undergoes predicate evaluation $V(d_{\text{local}}, \sigma)$. Structural constraints include: (a) mandatory presence of phoneme and grapheme keys; (b) regex conformity of phoneme symbols to International Phonetic Alphabet (IPA) subsets approved by the VIGÍA phonetic committee; (c) maximum grapheme length constraints $L_{\max}$ to prevent buffer-overflow artifacts in downstream C extensions. In the fourth phase, *Normalization and Unification*, valid entries are subjected to Unicode normalization $N_{\text{UFC}}$ (or configurable $N_{\text{UFD}}$) to eliminate canonical equivalence ambiguities. Phoneme strings are normalized via the function $N_p: \mathcal{P} \to \mathcal{P}_{\text{norm}}$ and graphemes via $N_g: \mathcal{G} \to \mathcal{G}_{\text{norm}}$. When multiple sources define conflicting mappings $(p, g_1)$ and $(p, g_2)$, the collision resolver $\mathcal{R}$ applies a deterministic precedence ordering encoded in $\theta$, typically lexicographic source priority, yielding a unified mapping $M^*$. In the fifth phase, *Sealing and Emission*, the final validated mapping $M^*$ is sealed as an immutable object. A composite integrity hash $h^* = H(M^* \oplus \theta \oplus \sigma)$ is computed, where $\oplus$ denotes concatenation of serialized representations. The object, together with metadata tuple $\mathcal{M} = (\tau, h_k, \sigma, \theta, h^*, t_{\text{stamp}})$, is emitted to downstream modules.

Input specifications are strictly typed to prevent runtime ambiguity. The parameter `source_paths` accepts a `List[Union[str, Path]]` comprising filesystem paths to raw phonetic dictionaries. Supported formats include JSON, TSV, and the VIGÍA native `.vpd` serialization. The `schema_id` parameter is a `str` referencing a schema record stored in `vigia/schema_registry.py`. The `config` parameter is an instance of `PhoneticLoaderConfig`, a frozen dataclass encapsulating $\theta$, including `normalization_form` (default `'NFC'`), `collision_policy` (default `'source_priority'`), and `hash_algorithm` (default `'sha256'`). The `audit_context` parameter, of type `AuditContext`, injects provenance metadata for chain-of-custody linkage. Output is emitted as a `ValidatedPhoneticMapping` object, an immutable, hash-addressed data structure containing: (i) `mapping`, a `FrozenDict[str, str]` representing the canonical phoneme-to-grapheme relation $M^*$; (ii) `provenance`, a `ProvenanceRecord` enumerating canonical paths, original digests, and temporal stamps; (iii) `integrity_hash`, the composite hash $h^*$ guaranteeing structural integrity.

The module provides strict deterministic guarantees essential for forensic science. First, bitwise reproducibility is enforced at every transformation boundary. Given identical input byte sequences $b$ and identical configuration state $\theta$, the output representation $b'$ is invariant across execution contexts, operating systems, and VIGÍA versions sharing this module. Formally:

$$\Pr[I(d, \theta, \sigma) \neq I(d, \theta, \sigma)] = 0$$

over independent executions. Second, the module adheres to the Daubert reliability criteria: (1) the ingestion algorithm is empirically testable and has been subjected to black-box regression testing; (2) the error rate is bounded—schema violations and path ambiguities are rejected rather than silently corrected, producing a known false-positive rate of zero and a false-negative rate governed solely by schema expressiveness; (3) the methodology is peer-reviewed within the VIGÍA technical consortium; and (4) general acceptance is documented through integration in accredited forensic phonetics laboratories. Third, compliance with GB/T 29360-2012 ensures that original dictionary sources are treated as electronic evidence: they are never modified in-place, access is logged, and integrity hashes are preserved. Fourth, the module's audit trail generation satisfies MLPS 2.0 (Multi-Level Protection Scheme 2.0) Level 3 requirements for data integrity and traceability, providing non-repudiable evidence of processing steps.

Within the VIGÍA ecosystem, `vigia/phonetic_loader.py` functions as the authoritative lexical substrate provider. The module `vigia/transcription_engine.py` consumes $M^*$ to constrain acoustic decoding lattices, ensuring that transcription hypotheses are drawn exclusively from validated phonetic inventories. The module `vigia/acoustic_feature_extractor.py` utilizes the phoneme alphabet $\mathcal{P}_{\text{norm}}$ as the controlled vocabulary for frame-level feature labeling, preventing out-of-vocabulary contamination. The module `vigia/forensic_report_generator.py` embeds the integrity hash $h^*$ and provenance metadata $\mathcal{M}$ into court-admissible reports, establishing the evidentiary chain for lexical substrates. Finally, `vigia/chain_of_custody_logger.py` receives cryptographic digests $h_k$ and processing events, preserving the chronological integrity of the ingestion process. `vigia/phonetic_loader.py` therefore represents a rigorously formalized forensic ingestion module whose mathematical architecture ensures temporal invariance and bitwise reproducibility, satisfying international standards for scientific evidence and cybersecurity compliance.

La operación de `vigia/phonetic_loader.py` se fundamenta formalmente en el álgebra relacional y la teoría de funciones deterministas. $$C: \mathcal{S} \to \mathcal{T}, \quad \forall s \in \mathcal{S}, \; C(s) = \tau$$

$$V: \mathcal{D} \times \Sigma \to \{0, 1\}$$

$$I: \mathcal{D} \times \Theta \times \Sigma \to \mathcal{M}, \quad I(d, \theta, \sigma) = M^*$$

siendo $\Theta$ el espacio de parámetros de configuración y $\mathcal{M}$ el codominio de mapeos fonéticos validados e inmutables. El axioma determinista fundamental exige:

$$\forall t_1, t_2 \in T, \quad I(d, \theta, \sigma; t_1) = I(d, \theta, \sigma; t_2)$$

$$C: \mathcal{S} \to \mathcal{T}, \quad \forall s \in \mathcal{S}, \; C(s) = \tau$$

где $\mathcal{T}$ — множество абсолютных, нормализованных и верифицированных по inode канонических путей. $$d = \{(p_i, g_j) \mid p_i \in \mathcal{P}, g_j \in \mathcal{G}\} \subseteq \mathcal{P} \times \mathcal{G}$$

Валидация схемы формализуется булевым предикатом:

$$V: \mathcal{D} \times \Sigma \to \{0, 1\}, \quad V(d, \sigma) = \begin{cases} 1, & \text{если } d \text{ соответствует схеме } \sigma \in \Sigma, \\ 0, & \text{иначе}. \end{cases}$$

Тогда детерминированное преобразование загрузки $I$ определяется как:

$$I: \mathcal{D} \times \Theta \times \Sigma \to \mathcal{M}, \quad I(d, \theta, \sigma) = M^*$$

где $\Theta$ — пространство конфигурационных параметров, а $\mathcal{M}$ — область значений валидированных неизменяемых фонетических отображений. Фундаментальный аксиома детерминизма требует:

Модуль реализует многостадийный конвейер загрузки, включающий пять основных фаз. В первой фазе, *каноническое разрешение путей и устранение псевдонимов*, алгоритм применяет функцию $C$ к каждому объявленному исходному пути $s$. Производится разыменование символических ссылок, абсолютизация относительных сегментов относительно судебного рабочего каталога $\omega$, а также разрешение псевдонимов файловой системы посредством отпечатков содержимого-inode. Результатом является дедуплицированная последовательность канонических путей $\tau_1, \tau_2, \dots, \tau_k$. Во второй фазе, *криптографическое отпечатывание до загрузки*, перед синтаксическим разбором каждый разрешённый файл хешируется с использованием криптографически стойкой функции $H$ (например, SHA-256), что даёт дайджест содержимого $h_k = H(\text{read}(\tau_k))$. Указанный дайджест немедленно регистрируется в `vigia/chain_of_custody_logger.py`, формируя поддающуюся аудиту запись происхождения. В третьей фазе, *извлечение схемы и структурная валидация*, модуль запрашивает в `vigia/schema_registry.py` активную схему $\sigma$, идентифицируемую параметром `schema_id`. Каждая запись словаря подвергается вычислению предиката $V(d_{\text{local}}, \sigma)$. Структурные ограничения включают: (a) обязательное наличие ключей phoneme и grapheme; (b) соответствие символов фонем регулярным выражениям, задающим подмножества Международного фонетического алфавита (IPA), утверждённые фонетическим комитетом VIGÍA; (c) ограничения максимальной длины графемы $L_{\max}$, предотвращающие артефакты переполнения буфера в последующих расширениях на языке C. В четвёртой фазе, *нормализация и унификация*, валидные записи подвергаются нормализации Unicode $N_{\text{UFC}}$ (или конфигурируемой $N_{\text{UFD}}$) для устранения неоднозначностей канонической эквивалентности. Строки фонем нормализуются функцией $N_p: \mathcal{P} \to \mathcal{P}_{\text{norm}}$, а графемы — функцией $N_g: \mathcal{G} \to \mathcal{G}_{\text{norm}}$. При конфликтных отображениях $(p, g_1)$ и $(p, g_2)$ из различных источников детерминистический резолвер коллизий $\mathcal{R}$ применяет правило приоритета, закодированное в $\theta$, как правило, лексикографический приоритет источника, формируя унифицированное отображение $M^*$. В пятой фазе, *уплотнение и эмиссия*, итоговое валидированное отображение $M^*$ запечатывается как неизменяемый объект. Вычисляется составной хеш целостности $h^* = H(M^* \oplus \theta \oplus \sigma)$, где $\oplus$ обозначает конкатенацию сериализованных представлений. Объект вместе с кортежем метаданных $\mathcal{M} = (\tau, h_k, \sigma, \theta, h^*, t_{\text{stamp}})$ эмитируется в нисходящие модули.

Спецификации входных и выходных данных строго типизированы для предотвращения неоднозначности на этапе исполнения. Параметр `source_paths` принимает значение типа `List[Union[str, Path]]` — пути файловой системы к сырым фонетическим словарям. Поддерживаемые форматы: JSON, TSV и родной формат VIGÍA `.vpd`. Параметр `schema_id` типа `str` является уникальным идентификатором, ссылающимся на запись схемы в `vigia/schema_registry.py`. Параметр `config` представляет собой экземпляр `PhoneticLoaderConfig` — неизменяемый класс данных, инкапсулирующий $\theta$, включая `normalization_form` (по умолчанию `'NFC'`), `collision_policy` (по умолчанию `'source_priority'`) и `hash_algorithm` (по умолчанию `'sha256'`). Параметр `audit_context` типа `AuditContext` инжектирует метаданные происхождения для привязки к журналу цепочки хранения. В качестве выходных данных формируется объект `ValidatedPhoneticMapping` — неизменяемая хеш-адресуемая структура данных, содержащая: (i) `mapping` типа `FrozenDict[str, str]` — каноническое отображение фонема—графема $M^*$; (ii) `provenance` типа `ProvenanceRecord` — канонические пути, исходные дайджесты и временные метки; (iii) `integrity_hash` — составной хеш $h^*$.

Модуль обеспечивает строгие детерминистические гарантии, критически важные для судебной экспертизы. Во-первых, побитовая воспроизводимость обеспечивается на каждой границе преобразования. При идентичных входных байтовых последовательностях $b$ и идентичном состоянии конфигурации $\theta$ выходное представление $b'$ инвариантно относительно контекста исполнения, операционной системы и версий VIGÍA, совместимых с данным модулем. Формально:

$$\Pr[I(d, \theta, \sigma) \neq I(d, \theta, \sigma)] = 0$$

по независимым исполнениям. Во-вторых, модуль соответствует критериям надёжности Daubert: (1) алгоритм загрузки эмпирически тестируем и подвергнут регрессионному тестированию методом чёрного ящика; (2) уровень ошибок ограничен — нарушения схемы и путевые неоднозначности отклоняются, а не исправляются скрытно, что даёт известную нулевую частоту ложноположительных результатов и частоту ложноотрицательных результатов, определяемую исключительно выразительностью схемы; (3) методология прошла рецензирование в рамках технического консорциума VIGÍA; (4) общее признание задокументировано интеграцией в аккредитованные судебно-фонетические лаборатории. В-третьих, соблюдение GB/T 29360-2012 («Технология судебной инспекции электронных данных») гарантирует, что исходные словари трактуются как электронные доказательства: они никогда не модифицируются по месту размещения, доступ логируется, а хеши целостности сохраняются. В-четвёртых, генерация журналов аудита модуля удовлетворяет требованиям уровня 3 MLPS 2.0 (Multi-Level Protection Scheme 2.0) к целостности и прослеживаемости данных, обеспечивая невозможность отказа от авторства этапов обработки.

`vigia/phonetic_loader.py` функционирует в качестве авторитетного поставщика лексического субстрата для ряда нисходящих судебных модулей. Модуль `vigia/transcription_engine.py` потребляет $M^*$ для ограничения решёток акустического декодирования, гарантируя, что гипотезы транскрипции извлекаются исключительно из валидированных фонетических инвентарей. Модуль `vigia/acoustic_feature_extractor.py` использует алфавит фонем $\mathcal{P}_{\text{norm}}$ в качестве контролируемого словаря для маркировки признаков на уровне фрейма, предотвращая загрязнение вне-словарными элементами. Модуль `vigia/forensic_report_generator.py` встраивает хеш целостности $h^*$ и метаданные происхождения $\mathcal{M}$ в допустимые в суде отчёты, устанавливая доказательственную цепочку для лексических субстратов. Наконец, `vigia/chain_of_custody_logger.py` принимает криптографические дайджесты $h_k$ и события обработки, сохраняя хронологическую целостность процесса загрузки. `vigia/phonetic_loader.py` представляет собой, таким образом, строго формализованный судебный модуль загрузки, унифицирующий загрузку фонетического словаря посредством канонического разрешения путей, предикатной валидации схем и детерминистической нормализации. Его математическая архитектура гарантирует временную инвариантность и побитовую воспроизводимость, удовлетворяя международным стандартам научных доказательств и требованиям кибербезопасности.

## 中文

`vigia/phonetic_loader.py` 是 VIGÍA 法医语音分析框架中的核心确定性摄取子系统。其首要法医目的在于消除语音词典资源加载阶段的非确定性变异。在法医言语科学中，音素到字素映射的完整性直接制约下游转写、说话人识别及语音比对管道的可靠性。通过将碎片化的源路径整合为单一规范摄取路径，该模块确保每一次法医检验均始于相同、已验证且可审计的词汇基底。此设计满足 Daubert 科学证据标准在《联邦证据规则》702 条下的可重复性前提，同时符合中国国家标准 GB/T 29360-2012《电子数据法庭科学鉴定技术规范》关于数据完整性的要求，并兼容网络安全等级保护制度 2.0（MLPS 2.0）对数据处理可追溯性的规定。

`vigia/phonetic_loader.py` 的运行严格建立在关系代数与确定性函数理论基础之上。设 $\mathcal{S}$ 为所有可能的源文件系统路径集合，包括相对路径、符号链接及环境相关描述符。规范路径解析算子定义为满射函数：

$$C: \mathcal{S} \to \mathcal{T}, \quad \forall s \in \mathcal{S}, \; C(s) = \tau$$

其中 $\mathcal{T}$ 表示绝对、规范化且经 inode 校验的规范路径集合。对于路径等价类满足单射条件：若 $s_1 \sim s_2$（表示解析至相同文件内容与元数据），则 $C(s_1) = C(s_2)$。设 $\mathcal{P} = \{p_1, p_2, \dots, p_m\}$ 为音素字母表，$\mathcal{G} = \{g_1, g_2, \dots, g_n\}$ 为字素字母表。原始语音词典 $d \in \mathcal{D}$ 可建模为有限有序对集合：

$$d = \{(p_i, g_j) \mid p_i \in \mathcal{P}, g_j \in \mathcal{G}\} \subseteq \mathcal{P} \times \mathcal{G}$$

模式验证形式化为布尔谓词：

$$V: \mathcal{D} \times \Sigma \to \{0, 1\}, \quad V(d, \sigma) = \begin{cases} 1, & \text{若 } d \text{ 符合模式 } \sigma \in \Sigma, \\ 0, & \text{否则}. \end{cases}$$

确定性摄取变换 $I$ 则定义为：

$$I: \mathcal{D} \times \Theta \times \Sigma \to \mathcal{M}, \quad I(d, \theta, \sigma) = M^*$$

其中 $\Theta$ 为配置参数空间（含规范化形式、源优先级向量、冲突解决策略等），$\mathcal{M}$ 为已验证的不可变音素-字素映射值域。基本确定性公理要求：

$$\forall t_1, t_2 \in T, \quad I(d, \theta, \sigma; t_1) = I(d, \theta, \sigma; t_2)$$

即给定相同输入与参数，映射具有时间不变性。该性质是满足 Daubert 标准可靠性要件的根本前提，也是实现按位可复现的理论基础。

该模块执行包含五个主要阶段的多级摄取管道。第一阶段为*规范路径解析与别名消除*：算法首先对每条声明的源路径 $s$ 应用函数 $C$。解引用符号链接，相对于法医工作目录 $\omega$ 绝对化相对路径段，并通过 inode-内容指纹解析文件系统别名。输出为去重后的规范路径序列 $\tau_1, \tau_2, \dots, \tau_k$。第二阶段为*摄取前密码学指纹提取*：在解析之前，每个已解析文件使用密码学安全哈希函数 $H$（如 SHA-256）进行哈希运算，生成内容摘要 $h_k = H(\text{read}(\tau_k))$。该摘要立即登记至 `vigia/chain_of_custody_logger.py`，建立可审计的来源记录。第三阶段为*模式获取与结构验证*：模块向 `vigia/schema_registry.py` 查询由 `schema_id` 标识的活动模式 $\sigma$。每条词典条目接受谓词评估 $V(d_{\text{local}}, \sigma)$。结构约束包括：(a) 必须存在音素键与字素键；(b) 音素符号须符合 VIGÍA 语音委员会批准的国际音标（IPA）子集正则表达式；(c) 字素最大长度约束 $L_{\max}$，以防止下游 C 扩展中的缓冲区溢出伪影。第四阶段为*规范化与统一化*：有效条目经 Unicode 规范化 $N_{\text{UFC}}$（或可配置的 $N_{\text{UFD}}$）处理，以消除规范等价歧义。音素串经函数 $N_p: \mathcal{P} \to \mathcal{P}_{\text{norm}}$ 规范化，字素经函数 $N_g: \mathcal{G} \to \mathcal{G}_{\text{norm}}$ 规范化。当多源定义冲突映射 $(p, g_1)$ 与 $(p, g_2)$ 时，冲突消解器 $\mathcal{R}$ 按编码于 $\theta$ 中的确定性优先级规则（通常为字典序源优先级）进行裁决，生成统一映射 $M^*$。第五阶段为*封存与输出*：最终已验证映射 $M^*$ 被封装为不可变对象。计算复合完整性哈希 $h^* = H(M^* \oplus \theta \oplus \sigma)$，其中 $\oplus$ 表示序列化表示的串联。该对象连同元组 $\mathcal{M} = (\tau, h_k, \sigma, \theta, h^*, t_{\text{stamp}})$ 一同向下游模块输出。

输入输出规格经过严格类型约束以杜绝运行时歧义。输入参数 `source_paths` 类型为 `List[Union[str, Path]]`，即原始语音词典的文件系统路径列表；支持格式包括 JSON、TSV 及 VIGÍA 原生 `.vpd`。参数 `schema_id` 为 `str` 类型，是唯一标识符，引用 `vigia/schema_registry.py` 中的模式记录。参数 `config` 为 `PhoneticLoaderConfig` 实例，该不可变数据类封装 $\theta$，包括 `normalization_form`（默认 `'NFC'`）、`collision_policy`（默认 `'source_priority'`）及 `hash_algorithm`（默认 `'sha256'`）。参数 `audit_context` 类型为 `AuditContext`，用于注入来源元数据以实现监管链关联。输出为 `ValidatedPhoneticMapping` 对象，这是一种不可变的哈希寻址数据结构，包含：(i) `mapping`，即 `FrozenDict[str, str]` 类型，表征规范音素-字素关系 $M^*$；(ii) `provenance`，即 `ProvenanceRecord` 类型，枚举规范路径、原始摘要及时间戳；(iii) `integrity_hash`，即复合哈希 $h^*$，用于保证结构完整性。

该模块提供法医科学所必需的严格确定性保证。第一，在每次变换边界强制实施按位可复现性。给定相同的输入字节序列 $b$ 与相同的配置状态 $\theta$，输出表示 $b'$ 在执行上下文、操作系统及共享本模块的 VIGÍA 版本间保持不变。形式化表达为：

$$\Pr[I(d, \theta, \sigma) \neq I(d, \theta, \sigma)] = 0$$

跨独立执行成立。第二，该模块符合 Daubert 可靠性标准：(1) 摄取算法具有可实证检验性，并经受黑盒回归测试；(2) 错误率有界——模式违规与路径歧义均被拒绝而非静默修正，产生已知的零假阳性率与仅受模式表达力制约的假阴性率；(3) 方法论经 VIGÍA 技术联盟同行评审；(4) 通过整合进入认证法医语音实验室，获得普遍接受性。第三，遵循 GB/T 29360-2012《电子数据法庭科学鉴定技术规范》确保原始词典来源作为电子证据处理：就地不可修改、访问留痕、完整性哈希保全。第四，模块的审计轨迹生成满足网络安全等级保护制度 2.0（MLPS 2.0）第三级对数据完整性与可追溯性的要求，提供不可抵赖的处理步骤证据，符合关键信息基础设施运营者在数据采集阶段的合规义务。

在 VIGÍA 生态系统内，`vigia/phonetic_loader.py` 作为权威词汇基底提供者为多个下游法医模块服务。模块 `vigia/transcription_engine.py` 消费 $M^*$ 以约束声学解码网格，确保转写假设仅源自已验证的音素库存。模块 `vigia/acoustic_feature_extractor.py` 以音素字母表 $\mathcal{P}_{\text{norm}}$ 作为帧级特征标注的受控词表，防止集外污染。模块 `vigia/forensic_report_generator.py` 将完整性哈希 $h^*$ 与来源元数据 $\mathcal{M}$ 嵌入可呈堂报告，建立词汇基底的证据链。最后，`vigia/chain_of_custody_logger.py` 接收密码学摘要 $h_k$ 与处理事件，保全摄取过程的时序完整性。综上所述，`vigia/phonetic_loader.py` 是一个严格形式化的法医摄取模块，通过规范路径解析、基于谓词的模式验证及确定性规范化，统一了语音词典加载流程；其数学架构确保时间不变性与按位可复现性，满足国际科学证据标准与网络安全合规要求。
