# Calibration / dataset archaeology — VIGÍA

**Date:** 2026-07-23
**Author:** Claude Fable (Claude Code, Mode 2), at maintainer request
**Scope:** Re-reading of the old "calibration" and "dataset" files to establish, for
each, whether it is LIVE (in the running decision path), TEST/FIXTURE, or FOSSIL
(historical, not consumed by executable code). Not a bug report — none of these are
defects. This is a map of dormant infrastructure so it stops being mistaken for
active machinery.

---

## Bottom line

**The entire calibration apparatus is opt-in and OFF in the default decision path.**
The default verdict comes from the closed-form Gaussian placeholder in the
LikelihoodEngine, `log_lr = z²/2` (`vigia/core/likelihood_ratio.py`, documented in
its own module docstring as *"placeholder operativo … pendiente de reemplazar por
calibración empírica … una vez que tengamos el dataset bootstrap completo"*).

Two independent consequences make this concrete:

1. **The LR calibrator only loads if a `calibration_path` is passed explicitly.**
   `VigiaPipeline` defaults `calibration_path: Optional[str] = None`
   (`vigia/pipeline/pipeline.py:191`); the calibrator is loaded only inside
   `if _LR_CALIBRATOR_AVAILABLE and LRCalibrator is not None and calibration_path:`
   (`pipeline.py:265`). The default `run_full` leaves it `None` → the pipeline logs
   `"uncalibrated"` (`pipeline.py:295`).

2. **Even the one dataset whose constants are baked into code feeds a SHADOW gate
   that does not change the verdict.** `signal_calibration_dataset_20260709.json`'s
   baseline constants live in `vigia/core/signal_quality_shadow.py`, whose own header
   says `B-116 — SignalQualityGate en MODO SOMBRA (WARN informativo)` and returns
   `"mode": "shadow_warn", "doctrine": "WARN informativo — no cap (decisión
   2026-07-22)"` (`signal_quality_shadow.py:2,84-86`). It evaluates and warns; it
   does not cap or flip a verdict.

So the statistically-flavoured, scikit-learn-based machinery (KDE, GridSearchCV,
Ledoit-Wolf shrinkage, logistic/isotonic calibration, pickled models) is real and
present in the tree, but **disconnected from the deterministic core.** This is why a
first read of the repo can mistake VIGÍA for an ML system: the vocabulary
(`dataset`, `fit`, `calibration`, `posterior`, `drift`, `PSI`) and the sklearn
tooling are there, while the actual decision path is exact and uncalibrated. VIGÍA is
not ML; it does not learn from cases; each case is independent. These files are the
residue of two attempts to *fit constants* to a reference set, neither of which was
wired into the verdict.

## Two waves of exploration

- **April–May 2026** — `fit_calibration.py`, `data/vigia_60_cases_dataset.json`,
  `data/dataset_test_cases.json`, `data/calibration_dataset.json`,
  `scripts/run_calibration.py`. The empirical-LR track (KDE per tool, Ledoit-Wolf
  covariance for the NLP cluster). Intended to replace the `z²/2` placeholder with a
  bootstrap-calibrated likelihood; produced `.pkl`/`calibrated_lr.json` but was never
  wired as the default. Likely also used to sanity-check the scorer/CAIE constants
  during early definition.
- **July 2026** — `signal_calibration_dataset_20260709.json`,
  `calibration_ladder_dataset_20260705.json`, `build_signal_calibration_dataset.py`.
  The B-116 signal-quality-gate track. Reached the tree but was deliberately cabled
  in **SHADOW/WARN** mode (no verdict effect) by the 2026-07-22 doctrine decision.

Neither track is adopted in the decision path. The LikelihoodEngine still uses the
documented closed-form placeholder by design.

## Open decision (for the maintainer — not taken here)

These are dormant, not broken. The standing question is binary:

1. **Retake** empirical calibration — wire `LRCalibrator` (logistic/isotonic) or the
   KDE models into the default path once a defensible bootstrap dataset exists, and
   promote the signal-quality gate out of SHADOW. This changes sealed verdicts and
   needs the full dry-run + adversarial + corpus protocol.
2. **Retire** it — move the fossil scripts/models/datasets to an `attic/` (or delete),
   leaving a one-line pointer to this doc, so the tree stops implying active ML
   machinery. Non-destructive first step: `attic/` move with a dry-run.

No files were moved, deleted, or modified in producing this assessment.
