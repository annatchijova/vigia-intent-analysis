| 概念 | 作用 | 确定性保障 |
|---|---|---|
| `ForensicBundle`（取证包） | 密封容器。存放证据图、溯因追踪与决策历史。 | 一经密封，即通过确定性整数运算计算链式哈希值。任何单比特改动都会使密封失效。 |
| `SignalOutput`（信号输出） | 所有取证工具的规范输出格式。 | 确保所有工具使用同一语言；数据在转换中不会丢失。 |
| `EvidenceEdge`（证据边） | 两条证据之间的关联。 | 稳定性由整数计数决定：一条边必须在 500 次自助重采样中至少出现 425 次（计数 ≥ 425）。是否纳入不依赖浮点近似。 |
| `EvidenceGraph`（证据图） | 证据片段间依赖关系的涌现图谱。 | 由频次计数构建，而非硬编码假设。 |
| `DecisionTrace`（决策追踪） | 对后验信念、风险评估与裁决三元组的正式记录。 | 裁决为离散状态：ACCEPT（接受）、REJECT（拒绝）或 ABSTAIN（弃权）。 |
| `PolicyRule` / `PolicySpec`（策略规则 / 策略规范） | 治理约束与可外部核查的策略容器。 | 规则依据整数阈值进行评估。 |
| `AbductionTrace`（溯因追踪） | 使用皮尔斯范畴对推理流水线进行的形式化追踪。 | 将发现过程的逻辑结构捕获为整数状态转移。 |
| `BundleBuilder`（包构建器） | 对 `ForensicBundle` 的静态封装工具，无需实例化即可密封数据包。 | 每次运行都以相同方式计算哈希链。 |
| `seal()` / `quick_verify()`（密封 / 快速校验） | `seal` 计算链式哈希；`quick_verify` 校验完整性。 | 两者均依赖精确的字节到整数哈希运算，绝不使用浮点比较。 |

术语表
- **自助稳定性（π）**：在本系统中，π 不是模糊的概率，而是在 500 次重采样中某条边出现次数的精确整数计数，并与固定阈值 425 进行比较。仅当计数足够高时才保留该边。
- **链式哈希（Chained Hash）**：由一系列加密指纹构成的链条，每一环均依赖于前一环，形成不可中断的确定性序列。
- **不可变层（Immutable Layer）**：设计规则，规定本层不得被上层修改，也不得导入上层代码。它是整个架构的基石。
- **SIFT**：接收 `ForensicBundle` 取证工件的外部核查系统。
- **溯因（皮尔斯）**：从观测事实中形成最佳解释的逻辑过程，在本模块中被形式化为可追踪的记录。
- **规范形式（Canonical Form）**：数据的唯一且无歧义表示，使得两个完全相同的取证包始终产生完全一致的序列化输出。

> - **皮尔斯的“第一性”**是测量前的原始电压潜能——纯粹的品质或可能性。
> - **“第二性”**是传感器遭遇物理事件时产生的实际电压尖峰——赤裸裸的事实。
> - **“第三性”**是将该尖峰解读为特定粒子探测结果的固件法则——一种起中介作用的规则或习惯。
> - **艾柯的符码**是标记与路由传感器数据包的通信协议，使下游仪器能够正确读取。
> - **格赖斯的准则**是对数据流效率的约束：说真话（质量准则）、说相关的话（关系准则）、简明扼要（方式准则）、提供所需信息（数量准则）。违反这些准则的传感器将发送噪声、误导性或冗余的数据。
> 
> 在 EBS v1 中，这些术语描述的是证据流的*逻辑拓扑*，而非超自然现象。
