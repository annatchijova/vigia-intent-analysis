| **Детерминированная целочисленная арифметика** | Точные вычисления с целыми числами или рациональными дробями (например, класс `Fraction` в Python), дающие идентичные результаты на любой архитектуре процессора. |
| **Shim** | Тонкий слой совместимости, связывающий две версии протокола или формата файла, позволяя им сосуществовать без конфликтов. |
| **Forensic Bundle** | Контейнер с защитой от несанкционированного доступа, упаковывающий цифровые доказательства вместе с метаданными и печатями целостности. |
| **Инвариант** | Правило, которое должно оставаться истинным на каждом этапе обработки; если оно нарушено, валидность системы разрушается. |
| **Цепочка сохранности** | Документированная, неразрывная передача доказательств от сбора до анализа и судебного представления. |

### 【Научное примечание】Семиотическая терминология — это массив датчиков, а не мистицизм

Имя модуля `semiotic_detector` и поля вроде `hypothesis_id` и `intent_type` заимствуют словарь из семиотических традиций **Чарльза Сандерса Пирса**, **Умберто Эко** и **Пола Грайса**. В контексте инженерии судебного программного обеспечения эти термины обозначают **слои классификации** — не отличающиеся от лабораторного массива датчиков, фиксирующих свет, температуру и давление.

- **Знак** (Пирс) — это просто обнаружимый паттерн в данных.
- **Код** (Эко) — это протокол, отображающий паттерны на дискретные категории.
- **Интенция** (Грайс) — это выводимая коммуникативная цель, стоящая за наблюдаемым действием.

Это **эпистемологические инструменты**, а не метафизические утверждения. Воспринимать их как мистицизм — всё равно что называть спектрофотометр «магией» только потому, что он сопоставляет длины волн с химическими идентичностями. Модуль аудита обеспечивает эту строгость, гарантируя, что каждая классификация (`hypothesis_id`, связанный с одним и тем же непротиворечивым `intent_type`) остаётся логически когерентной и воспроизводимой.

## 中文

### 本模块是什么？
`scripts/pre_release_check.py` 是 VIGÍA 取证套件（VIGÍA Forensic Suite）的自动化守门人。在任何新代码被接纳之前，该脚本会将整个代码库视为一套蓝图——绝不执行程序本身——并搜寻五类特定风险：对已弃用模块的违禁导入、违规的架构捷径、隐藏的 shadow_mode 运行模式、缺乏显式兼容层的版本共存文件对，以及可能破坏加密哈希值的可复现性的非确定性数值路径。它设计为在持续集成/持续交付（CI/CD）流水线中运行，或作为 pre-commit hook（提交前钩子），一旦发现关键问题即阻止发布。

### 核心概念

| 概念 | 通俗解释 | 对取证科学为何重要 |
|---|---|---|
| **静态审计（AST 遍历）** | 不运行代码而阅读其结构，如同在建筑开工前检查设计图纸。 | 审计过程本身无法篡改证据，也不会引入运行时副作用。 |
| **违禁导入** | 试图加载已弃用模块，例如旧版 `ebs` 或未带 `v2` 后缀的 `semiotic_detector`。 | 防止过时或未经验证的代码路径进入保管链。 |
| **Seal 违规** | `ForensicBundle` 类自行定义了 `seal()` 方法，而非将密封操作委托给 `BundleBuilder`。 | 违反了架构不变量：每一次密封都必须经过受控、可审计的工作流。 |
| **Shadow Mode 导入** | 任何包含关键字 `shadow_mode` 的导入语句。 | 表明存在实验性或隐藏的执行路径，绕过了标准日志与监管。 |
| **版本填充层缺失** | 同一目录下同时存在 `_v1` 和 `_v2` 后缀的文件，却缺少显式兼容层。 | 造成**逻辑断裂**，分析人员可能在不知情的情况下混用不兼容的数据模式。 |
| **浮点入哈希路径** | 在参与加密哈希计算的函数中使用 `math.log` / `math.log2`，且数据流未经过 `Fraction` 或 `_round_floats` 处理。 | 取证哈希必须依赖**确定性整数运算**；中间浮点值在不同 CPU 架构（ARM 与 x86）上可能产生差异，导致指纹不可复现。 |
| **Hypothesis ID 冲突** | 同一文件中同一 `hypothesis_id` 多次出现，且每次关联的 `intent_type` 不同。 | 意味着对同一**取证工件**的分类相互矛盾，破坏了可复现的同行评议。 |
| **严重程度级别** | 关键（阻止发布）、警告（需提供书面说明）、信息（仅供参考）。 | 对应取证分类：证据要么不可采纳，要么存疑，要么仅作为背景记录。 |

### 术语表

| 术语 | 定义 |
|---|---|
| **AST（抽象语法树）** | 对源文件中每条指令的层级化映射，类似于指令的家谱树。 |
| **Pre-commit Hook（提交前钩子）** | 一种自动化检查点，在代码变更被永久接纳进代码库之前将其拦截。 |
| **CI/CD（持续集成/持续交付）** | 自动化的构建、测试与封装软件的生产线。 |
| **加密哈希（Cryptographic Hash）** | 数据的确定性数值指纹。任何细微改动都会产生明显不同的指纹。 |
| **确定性整数运算** | 使用整数或精确有理分数（例如 Python 的 `Fraction` 类）进行的计算，在任何处理器架构上都得出完全相同的结果。 |
| **Shim（填充层）** | 一种轻量级的转换层，用于桥接两个版本的协议或文件格式，使其能够无冲突共存。 |
| **取证工件（Forensic Bundle）** | 用于打包数字证据及其元数据与完整性封签的防篡改容器。 |
| **不变量（Invariant）** | 在处理过程的每个阶段都必须保持为真的规则；一旦打破，系统的有效性即告崩溃。 |
| **保管链（Chain of Custody）** | 证据从收集、分析到法庭呈示的全程有文件记录、不间断的移交过程。 |
