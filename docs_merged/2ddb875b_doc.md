**Mathematical Foundations**

The theoretical underpinnings of `ci_gate.py` rest on information-theoretic and algebraic constructs that ensure deterministic evaluability. Let $\mathcal{A}$ denote the finite artifact space comprising all possible candidate builds. Each artifact $A \in \mathcal{A}$ induces a joint probability distribution $P_A(X,Y)$ over a feature space $\mathcal{F}_X \times \mathcal{F}_Y$, where $X$ represents observable forensic features (e.g., entropy pools, file carver signatures, timeline granules) and $Y$ represents ground-truth labels or reference classifications. The Mutual Information between $X$ and $Y$ under artifact $A$ is defined as:

$$I_A(X;Y) = \sum_{x \in \mathcal{F}_X} \sum_{y \in \mathcal{F}_Y} P_A(x,y) \log \frac{P_A(x,y)}{P_A(x)P_A(y)}$$

where logarithms are taken in base $e$ (nats) for analytical convenience, though the framework is base-invariant provided consistency is maintained across the baseline and candidate. The module operates exclusively within the field of rational numbers $\mathbb{Q}$. Consequently, all probability masses are represented as exact fractions $p/q$, and the MI computation is carried out by deterministic symbolic or rational fixed-point methods, explicitly excluding floating-point arithmetic from the critical comparison path. This exclusion is essential because floating-point operations introduce non-deterministic rounding behaviors across processor architectures, which would violate the evidentiary reproducibility mandate.

Let $A_r$ denote the certified reference baseline artifact and $A_c$ the candidate artifact submitted for CI validation. The MI drift is defined as the absolute difference:

$$\Delta I = |I_{A_c}(X;Y) - I_{A_r}(X;Y)|$$

The rigid rational threshold is codified as:

$$\tau = \frac{1}{100}$$

The deterministic acceptance criterion is therefore the logical conjunction:

$$V = \text{PASS} \iff \left( \Delta I \leq \tau \right) \land \left( \text{Acc}(A_c) \geq \text{Acc}(A_r) \right) \land \left( H(A_c) \in \mathcal{H}_{\text{allowed}} \right)$$

where $\text{Acc}(A)$ denotes the analytical accuracy metric computed by the VIGÍA analytical engine, and $H: \mathcal{A} \to \{0,1\}^{256}$ is the SHA-256 hash function ensuring bitwise integrity. The set $\mathcal{H}_{\text{allowed}}$ is maintained by the companion module `vigia_baseline` and represents the transitive closure of all hashes explicitly approved by the chain-of-custody protocol managed by `vigia_chain`.

If the chain is broken or the signature invalid, the algorithm terminates with $V = \text{FAIL}$ and exit code 1.

*Stage 2: Structural Isomorphism.* The module loads the schema $S$ registered in `vigia_baseline` and verifies that the candidate artifact is structurally isomorphic to the reference. This includes matching the exact set of exported symbols, configuration parameter keys, and analytical plugin load order. Structural mismatches are treated as catastrophic failures because they indicate potential code path alterations that could affect downstream entropy distributions.

*Stage 3: Entropic Profile Extraction.* Leveraging the probability tables provided by `vigia_entropy`, the module reconstructs the exact rational probability distributions $P_{A_c}$ and $P_{A_r}$. These tables are pre-computed to avoid runtime non-determinism and are stored as normalized fractions with a common denominator bound to prevent combinatorial explosion.

*Stage 4: Exact Mutual Information Computation.* Using rational arithmetic libraries, the module evaluates $I_{A_c}$ and $I_{A_r}$ from the reconstructed distributions. *Stage 5: Drift Quantification and Thresholding.* The module computes $\Delta I = |q_c - q_r|$ as an exact rational subtraction. It then evaluates the predicate $\Delta I \leq \frac{1}{100}$. *Stage 7: Immutable Logging.* Upon conclusion, the module writes a JSON verdict object to `vigia_audit` and appends a tamper-evident entry to `vigia_evidence`. Взаимная информация между $X$ и $Y$ при артефакте $A$ определяется следующим образом:

$$I_A(X;Y) = \sum_{x \in \mathcal{F}_X} \sum_{y \in \mathcal{F}_Y} P_A(x,y) \log \frac{P_A(x,y)}{P_A(x)P_A(y)}$$

где логарифмы берутся по основанию $e$ (наты) для аналитического удобства, хотя инвариантность относительно основания сохраняется при условии согласованности между базовой линией и кандидатом. Модуль функционирует исключительно в поле рациональных чисел $\mathbb{Q}$. Следовательно, все вероятностные массы представляются в виде точных дробей $p/q$, а вычисление MI осуществляется символическими методами или методами рациональной арифметики с явным исключением операций с плавающей точкой из критического пути сравнения. Данное исключение является существенным, поскольку операции с плавающей точкой вносят недетерминированные погрешности округления, различающиеся на различных процессорных архитектурах, что нарушало бы требование доказательственной воспроизводимости.

Пусть $A_r$ — сертифицированный референтный артефакт базовой линии, а $A_c$ — кандидатный артефакт, представленный на CI-валидацию. Дрейф взаимной информации определяется как абсолютная разность:

$$\Delta I = |I_{A_c}(X;Y) - I_{A_r}(X;Y)|$$

Жёсткая рациональная граница закодирована в виде:

$$\tau = \frac{1}{100}$$

Таким образом, детерминированный критерий приёмки представляет собой логическую конъюнкцию:

$$V = \text{PASS} \iff \left( \Delta I \leq \tau \right) \land \left( \text{Acc}(A_c) \geq \text{Acc}(A_r) \right) \land \left( H(A_c) \in \mathcal{H}_{\text{allowed}} \right)$$

где $\text{Acc}(A)$ обозначает метрику аналитической точности, вычисляемую аналитическим движком VIGÍA, а $H: \mathcal{A} \to \{0,1\}^{256}$ — хеш-функция SHA-256, обеспечивающая побитовую целостность. Множество $\mathcal{H}_{\text{allowed}}$ поддерживается сопутствующим модулем `vigia_baseline` и представляет транзитивное замыкание всех хешей, явно одобренных протоколом цепочки сохранения, администрируемым модулем `vigia_chain`.

**Описание алгоритма**

Алгоритм, реализуемый модулем `ci_gate.py`, функционирует как поэтапный монотонный конвейер верификации. Каждый этап является идемпотентным и порождает дополняемую только присоединением доказательственную трассу.

*Этап 1: Погружение и верификация цепочки сохранения.* Модуль принимает четыре основных входных потока: (1) путь к файлу кандидатного артефакта $F_c$; (2) путь к запечатанному референтному артефакту $F_r$; (3) JSON-дескриптор энтропии, сгенерированный модулем `vigia_entropy`; (4) манифест цепочки сохранения от модуля `vigia_chain`. Сначала вычисляется $h_c = H(F_c)$ и проверяется, что $h_c$ обратно ссылается на неразрывную последовательность сохранения, завершающуюся корневым сертификатом, хранимым в `vigia_sign`. При нарушении цепочки или недействительности подписи алгоритм завершается с $V = \text{FAIL}$ и кодом возврата 1.

*Этап 2: Структурный изоморфизм.* Модуль загружает схему $S$, зарегистрированную в `vigia_baseline`, и верифицирует структурный изоморфизм между кандидатным и референтным артефактами. Проверке подлежат точное множество экспортируемых символов, ключи параметров конфигурации и порядок загрузки аналитических подключаемых модулей. Структурные несоответствия квалифицируются как катастрофические отказы, поскольку они свидетельствуют об изменениях траекторий исполнения кода, способных повлиять на нисходящие энтропийные распределения.

*Этап 3: Извлечение энтропийного профиля.* Используя таблицы вероятностей, предоставленные `vigia_entropy`, модуль реконструирует точные рациональные распределения вероятностей $P_{A_c}$ и $P_{A_r}$. Указанные таблицы предвычисляются для исключения недетерминизма времени выполнения и хранятся в виде нормализованных дробей с ограниченным общим знаменателем, предотвращающим комбинаторный взрыв.

*Этап 4: Точное вычисление взаимной информации.* При помощи библиотек рациональной арифметики модуль вычисляет $I_{A_c}$ и $I_{A_r}$ на основе реконструированных распределений. Все промежуточные суммирования выполняются с точным учётом числителя и знаменателя. Результатом служит пара рациональных чисел $(q_c, q_r) \in \mathbb{Q}^2$.

*Этап 5: Количественная оценка дрейфа и пороговая обработка.* Модуль вычисляет $\Delta I = |q_c - q_r|$ как точное рациональное вычитание, после чего вычисляет предикат $\Delta I \leq \frac{1}{100}$. Поскольку оба операнда рациональны, сравнение детерминировано и сводится к целочисленному перекрёстному умножению: $100 \cdot |q_c - q_r| \leq 1$.

*Этап 6: Анализ регрессии точности.* Аналитическая точность оценивается по метрикам, экспортируемым модулем `vigia_verdict`. Кандидат должен удовлетворять условию $\text{Acc}(A_c) \geq \text{Acc}(A_r)$. Строгое неравенство не требуется; допускается эквивалентность. Однако любое снижение, каким бы инфинитезимальным оно ни было в терминах плавающей точки, фиксируется точно рациональным представлением и инициирует отклонение.

*Этап 7: Неизменяемое протоколирование.* По завершении модуль записывает JSON-объект вердикта в `vigia_audit` и добавляет запись, защищённую от подделки, в `vigia_evidence`. Запись содержит рациональную строку дрейфа (например, `"1/200"`), дельту точности, хеш трассы $\Lambda = H(h_c \| h_r \| \Delta I)$ и метку времени в формате ISO-8601.

  - `module_hash`: Константная строка `"2ddb875b"`.

**Детерминированные гарантии**

Модуль обеспечивает ряд формальных гарантий, критически важных для судебной допустимости:
1. **Архитектурная воспроизводимость**: Поскольку вся арифметика критического пути выполняется в $\mathbb{Q}$, вердикт $V$ идентичен в средах x86_64, ARM64 и RISC-V. Отсутствуют расхождения, обусловленные спецификой блоков операций с плавающей точкой.
2. **Известная граница ошибки**: Порог дрейфа MI $\tau = 1/100$ функционирует как юридически устанавливаемая частота ошибок в рамках стандарта Daubert. Система категорически отклоняет любой кандидат, у которого информационно-теоретическая дивергенция превышает данный опубликованный предел.
3. **Временная стабильность**: При идентичных входных данных модуль порождает идентичные выходные данные и идентичные хеши трассы $\Lambda$ в любой момент времени. Алгоритм не содержит псевдослучайных компонентов, не зависит от времени суток и не подвержен вариациям порядка, индуцируемым параллелизмом.
4. **Доказательство факта воздействия**: Любое побитовое изменение $F_c$, $F_r$ или карты энтропии необходимо изменяет $h_c$, $h_r$ или вычисленное $\Delta I$, что, в свою очередь, модифицирует $\Lambda$. Запись в `vigia_evidence` тем самым криптографически привязана к точному состоянию оцениваемых объектов.
5. **Непреложный регрессионный порог**: Проверки точности и MI логически объединены конъюнкцией AND без механизма отмены. Административный обход отсутствует, что исключает принуждение шлюза к одобрению деградированного артефакта.

## 中文

模块 `ci_gate.py`（加密哈希标识符：`2ddb875b`）是 VIGÍA 取证流水线的确定性准入闸门，定位于持续集成（CI）构建生成与具有证据效力的发布认证之间的关键控制节点。在取证工具链的语境下，分析可复现性并非仅仅是软件工程的期望属性，而是法律前置条件；该模块因此执行对回归的零容忍策略。其核心目的在于对候选构建产物与经加密封印的认证参考基线进行精确且与架构无关的比对。任何导致分析精度退化，或致使互信息（MI）漂移超出严格有理数阈值 $\tau = \frac{1}{100}$ 的偏差，均会被立即、无协商地拒绝。作为符合 SANS 规范的交付物，`ci_gate.py` 确保 VIGÍA 平台的每一次发布均维持与其最初验证时所依据的基线相同的证据级标准。

**数学基础**

`ci_gate.py` 的理论根基建立在信息论与代数构造之上，以确保评估的确定性。设 $\mathcal{A}$ 为包含所有可能候选构建的有限产物空间。每个产物 $A \in \mathcal{A}$ 在特征空间 $\mathcal{F}_X \times \mathcal{F}_Y$ 上诱导一个联合概率分布 $P_A(X,Y)$，其中 $X$ 表示可观测的取证特征（如熵池、文件恢复签名、时间线粒度），$Y$ 表示真值标签或参考分类。产物 $A$ 下 $X$ 与 $Y$ 的互信息定义为：

$$I_A(X;Y) = \sum_{x \in \mathcal{F}_X} \sum_{y \in \mathcal{F}_Y} P_A(x,y) \log \frac{P_A(x,y)}{P_A(x)P_A(y)}$$

此处对数取自然底 $e$（单位为纳特，nats），但只要在基线与候选之间保持一致，该框架与对数底无关。模块完全在有理数域 $\mathbb{Q}$ 内运算。因此，所有概率质量均表示为精确分数 $p/q$，MI 计算通过符号法或有理定点法完成，并显式排除关键比对路径中的浮点运算。此项排除至关重要，因为浮点运算在不同处理器架构之间会引入非确定性的舍入行为，从而违反证据可复现性之要求。

设 $A_r$ 为经认证的参考基线产物，$A_c$ 为提交 CI 验证的候选产物。互信息漂移定义为绝对差值：

$$\Delta I = |I_{A_c}(X;Y) - I_{A_r}(X;Y)|$$

刚性有理阈值编码为：

$$\tau = \frac{1}{100}$$

于是，确定性准入判据为如下逻辑合取式：

$$V = \text{PASS} \iff \left( \Delta I \leq \tau \right) \land \left( \text{Acc}(A_c) \geq \text{Acc}(A_r) \right) \land \left( H(A_c) \in \mathcal{H}_{\text{allowed}} \right)$$

其中 $\text{Acc}(A)$ 表示由 VIGÍA 分析引擎计算的分析精度指标，$H: \mathcal{A} \to \{0,1\}^{256}$ 为用于保障逐位完整性的 SHA-256 哈希函数。集合 $\mathcal{H}_{\text{allowed}}$ 由配套模块 `vigia_baseline` 维护，代表由 `vigia_chain` 管理的保管链协议所明确批准的全部哈希值的传递闭包。

**算法描述**

`ci_gate.py` 执行的算法表现为一个分阶段的单调验证流水线。每一阶段均具有幂等性，并生成仅可追加的证据级追踪记录。

*阶段 1：摄入与保管链核验。* 模块接收四项主要输入：（1）候选产物文件路径 $F_c$；（2）封印的参考基线路径 $F_r$；（3）由 `vigia_entropy` 生成的熵描述 JSON；（4）由 `vigia_chain` 提供的保管链清单。模块首先计算 $h_c = H(F_c)$，并核验 $h_c$ 能否向后关联至一条未中断的保管序列，且该序列终止于 `vigia_sign` 中存储的根证书。若保管链断裂或签名无效，算法即以 $V = \text{FAIL}$ 及返回码 1 终止。

*阶段 2：结构同构性检查。* 模块加载注册于 `vigia_baseline` 中的模式 $S$，并核验候选产物与参考产物之间是否存在结构同构。检查内容包括导出符号集、配置参数键以及分析插件加载顺序的精确匹配。结构差异被视为灾难性故障，因为其表明代码执行路径可能发生变更，进而影响下游熵分布。

*阶段 3：熵特征提取。* 模块利用 `vigia_entropy` 提供的概率表，重构精确的有理概率分布 $P_{A_c}$ 与 $P_{A_r}$。这些表经过预计算以消除运行时非确定性，并以归一化分数形式存储，其公分母设有上界以防止组合爆炸。

*阶段 4：精确互信息计算。* 模块借助有理算术库，基于重构分布求取 $I_{A_c}$ 与 $I_{A_r}$。所有中间求和均对分子与分母进行精确跟踪。计算结果为一组有理数对 $(q_c, q_r) \in \mathbb{Q}^2$。

*阶段 5：漂移量化与阈值判定。* 模块以精确有理减法计算 $\Delta I = |q_c - q_r|$，随后判定谓词 $\Delta I \leq \frac{1}{100}$。由于两操作数均为有理数，该比较具有确定性，并可归约为整数交叉乘法：$100 \cdot |q_c - q_r| \leq 1$。

*阶段 6：精度回归分析。* 分析精度通过 `vigia_verdict` 导出的指标进行评估。候选产物须满足 $\text{Acc}(A_c) \geq \text{Acc}(A_r)$。此处不要求严格不等式，等价情形亦可接受。然而，任何精度下降——即便在浮点意义上为无穷小——亦会被有理表示精确捕获并触发拒绝。

*阶段 7：不可篡改日志记录。* 验证结束后，模块向 `vigia_audit` 写入 JSON 格式的裁决对象，并向 `vigia_evidence` 追加一条防篡改记录。该记录包含有理漂移字符串（例如 `"1/200"`）、精度差值、追踪哈希 $\Lambda = H(h_c \| h_r \| \Delta I)$ 以及 ISO-8601 时间戳。

**
